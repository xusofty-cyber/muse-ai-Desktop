# 操作指南：内置 Mihomo 代理分流与多账号独立出口队列

## 1. 目标与适用范围
本手册指导用户与操作人员如何在 Muse Desktop 中使用内置的 Mihomo (Clash.Meta) 代理引擎，通过配置多个机场订阅与本地 YAML 配置文件，为不同的 Muse AI / Meta AI 账号分别指定独立的节点出口队列与代理模式，实现真正的物理级 IP 隔离与防风控关联。

---

## 2. 前置准备与内核发现机制

Muse Desktop 会自动按优先级探测以下路径中的 Mihomo 核心二进制：
* **Windows**：
  * 应用内置路径：`bin/mihomo/mihomo-windows-amd64-v3.exe`、`bin/mihomo/mihomo.exe`；
  * 数据目录路径：`%APPDATA%\Muse\mihomo\mihomo.exe`；
  * 系统路径：环境变量 `PATH` 中的 `mihomo`。
* **Linux (Ubuntu / Debian / Arch)**：
  * 系统包路径：`/usr/bin/mihomo`、`/usr/local/bin/mihomo`（`sudo apt install mihomo` 或手动放置）；
  * 数据目录路径：`~/.config/Muse/mihomo/mihomo`；
  * Clash Verge 预设路径：`/usr/bin/verge-mihomo`。
* **macOS**：
  * `/usr/local/bin/mihomo` 或 `~/Library/Application Support/Muse/mihomo/mihomo`。

> **提示**：若未检测到内核，设置界面的状态栏会显式提示“内核文件未找到”，放置二进制后点击重新拉取即可自动就绪。

---

## 3. 操作步骤 (Step-by-Step)

### 步骤 1：开启内置 Mihomo 并配置多源节点池（多订阅与本地 YAML）
1. 启动 Muse 客户端，点击左下角控制中心 `⚙` 或按快捷键 `Ctrl + ,` 打开【设置】页面；
2. 切换至 **【网络与代理】** 标签页，连接模式勾选 **【内置 Mihomo 智能分流】**；
3. **添加远程机场订阅**：
   - 点击 **`+ 添加订阅`** 按钮，展开添加抽屉；
   - 输入自定义源名称（如“默认订阅A”）及购买的机场 Clash 订阅链接，点击“保存并拉取”；
4. **导入本地 Clash YAML 配置文件**：
   - 点击 **`📂 导入本地 YAML`** 按钮，在弹出的系统文件选择框中选择本地已有的 `.yaml` 或 `.yml` 节点文件；
   - 系统自动解析提取有效节点；
5. **智能防冲突合并引擎**：
   - 客户端遍历所有处于启用状态的源，自动为重名节点添加 `[源名称] 节点名` 前缀（例如 `[默认订阅A] 美国01`），多源同时开启合并为一个节点池；
   - 点击 **【全部同步】** 可一键刷新所有远程源。

---

### 步骤 2：全节点批量延迟测速（可选）
1. 在设置面板中点击 **【一键全节点测速】**；
2. 系统将通过内部 REST API 对全部合并节点进行并发延迟探测；
3. 节点卡片上将实时渲染各节点的延迟毫秒数与健康色标：
   - 🟢 **绿色**（< 300ms）：高速推荐节点
   - 🟡 **黄色**（300ms ~ 800ms）：普通可用节点
   - 🔴 **红色**（> 800ms 或超时）：不建议作为主用节点

---

### 步骤 3：为账号配置独立代理模式与专属出口队列
1. 点击底部 Dock 栏左侧的 **宫格图标 (⊞)** 或按下快捷键 **`Ctrl + Shift + G`**，打开 **九宫格账号管理看板**；
2. 找到需要配置的账号卡片，点击 **【编辑详情】**；
3. **选择账号专属网络模式**：
   - **跟随全局 (`inherit`)**：跟随设置面板选定的连接模式；
   - **强制走系统代理/TUN 虚拟网卡 (`system`)**：**主力推荐**。即便全局开启了 Mihomo，该账号也强制直连 Clash Verge / Sing-box 的 TUN 网卡直通；
   - **内置 Mihomo 专属出口队列 (`mihomo`)**：为该账号启用物理级独立 Inbound 端口与出口队列；
   - **直接连接 (`direct`)**：绕过任何代理直连；
   - **手动代理覆盖 (`custom`)**：单独指定专用的 HTTP / SOCKS5 代理。
4. **批量添加节点到出口队列（Mihomo 模式下）**：
   - **1-Click 快捷添加**：点击 `+ 全部美国`、`+ 全部香港`、`+ 全部日本`、`+ 全部新加坡` 或 `+ 全部节点`，秒级将对应地区的节点一键填入队列；
   - **高级批量选择器**：点击 **`＋ 批量选择节点...`**，弹出模态框支持关键词搜索、地区过滤胶囊、全选/反选与去重批量添加；
   - **队列顺序与优先级**：排在首位的为 **主用节点 (👑)**，后面的为故障自动转移备用节点。
5. 点击 **【保存并应用】**。

---

### 步骤 4：无感切换与出口隔离验证
1. 在 Dock 栏或看板中点击切换至该账号；
2. Electron 将自动把该账号的 Session 请求路由到为它单独分配的 Inbound 端口（如 `18001`、`18002`...）；
3. 经由该端口的所有流量将被定向到该账号专属的策略组中，与其他账号完全隔绝。

---

### 步骤 5：账号与代理配置跨机/跨系统备份与热迁移
当更换新电脑（或在 Windows 与 Ubuntu / Linux 之间迁移）时：
1. **一键导出**：在九宫格看板顶部点击 **【📤 导出配置】**，保存为 `.json` 备份文件；
2. **一键恢复**：在新设备上安装 Muse 后，点击 **【📥 导入配置】**，选择该备份文件，17+ 账号的所有配置、分组、订阅源与代理队列秒级完整还原；
3. **免密免扫码迁移**：若需连同所有账号的登录会话（Cookies）一并克隆，可直接打包复制完整数据目录（Windows: `%APPDATA%\Muse`，Linux: `~/.config/Muse`）到新环境覆盖即可。

## 4. 常见问题排查与 FAQ

| 常见现象 / 错误提示 | 产生原因 | 解决处置方案 |
| :--- | :--- | :--- |
| **内核文件未找到** | 对应路径下无该架构的 Mihomo 可执行文件 | Windows 放置 `mihomo.exe` 至 `bin/mihomo/`；Ubuntu 运行 `sudo apt install mihomo` 或放置 `/usr/local/bin/mihomo` 并赋权 `chmod +x` |
| **订阅拉取失败 (403/超时)** | 机场订阅防刷限制或需要代理访问 | 检查订阅 URL 是否准确；若机场封锁直连，可先在系统配置全局代理后再同步 |
| **本地 YAML 导入节点为 0** | YAML 格式非标准 Clash proxies 列表 | 检查 YAML 文件内是否包含 `proxies:` 顶级数组定义 |
| **跨机场节点名称重复** | 多个订阅源使用了相同的名字（如“香港01”） | 系统已内置自动防冲突重命名，自动附加 `[源名称]` 前缀，无需人工干预 |
| **切换账号后网页无法加载** | 账号队列中配置的所有节点均已失效 | 在设置中点击【一键全节点测速】，更换该账号队列中的主备节点 |
| **如何查看底层内核日志？** | 排查复杂网络握手或订阅解析细节 | 日志实时存储于应用数据目录：`<userData>/mihomo/mihomo.log` |
