## 2. 链接打开

**起因**：设置 > 通用 >「Meta 账户」点了没反应。

**原因**：`*.meta.com` 被当成站内地址，打开新窗口的请求被直接拦掉；如果交给系统浏览器，又没有当前账号的登录状态。

**改法**
- Meta 账户中心、站内分享 / 文档 / 产物链接，改为在应用内**用当前账号的会话**打开独立窗口。
- 同一账号打开同一站点时复用已有窗口；窗口标题带账号名。
- 附件和导出链接直接用当前账号下载，不弹出空白窗口。
- 站内链接改为按完整地址比较，修复指向首页、或路径相同但参数不同时点了没反应。
- 主窗口里的普通跳转，只有 `accountscenter.*` 改为弹窗；服务端重定向一律不改道，不会截断登录和切换账号。
- 真正的站外链接（包括 `l.facebook.com` 这类中转）仍交给系统浏览器打开。

## 5. 出口 IP 隔离

入口：设置 > Mihomo > 出口 IP 隔离。

**背景**：按 11-15 的备份统计，18 个账号只用了 3 种首节点（分别有 10 / 6 / 2 个账号共用），策略都是 `fallback`，所以实际只有 3 个出口 IP。节点池里有 43 个不同的服务器，节点数量是够的。

| 功能 | 说明 |
|---|---|
| **WebRTC 防护** | 所有页面设置为 `disable_non_proxied_udp`，网页拿不到真实 IP。默认开启，可在设置页关闭 |
| **① 检测各账号当前出口** | 用每个账号自己的会话查询 ipinfo.io，失败时改用 api.ipify.org；标出和别的账号共用出口的账号 |
| **② 测试全部节点出口** | 另起一个临时 Mihomo，逐个节点实测出口，并把实际是同一出口的节点归为一组；测完立即停止并删除临时配置，不影响正在使用的账号 |
| **③ 生成方案 → 应用** | 每个账号的主出口互不相同，备用节点也不和别人共用出口；能不换就不换；改派时优先同国家 / 地区、非低倍率、低延迟；出口不够时，多出的账号保持原样并列出；应用时可同时开启严格隔离 |
| **定期自动检测** | 默认关闭，间隔可选 15 分钟 – 12 小时。出现多账号共用出口、出口 IP 变化、走 Mihomo 的账号无法联网时发系统通知；同一问题只提醒一次；全部账号失败视为断网，只报一条；通知里不含 IP |

**端口规则**：每个账号按 id 固定一个端口，从 18001 开始，跳过控制端口，账号数量不限。已验证 10、50、200 个账号时端口都各不相同。端口独立不等于出口 IP 独立：出口取决于账号的节点队列。

## 8. 开发环境：Electron 启动权限

**报错**

```
Sandboxed processes cannot read ...\node_modules\electron\dist: its ACL has an entry for an AppContainer package SID but none for ALL APPLICATION PACKAGES
```

**原因**：项目文件夹继承了一条只给某个特定应用的授权，最可能来自 AWS Quick 桌面应用访问这个目录时添加的。Electron 的沙盒进程因此读不到自带的程序文件。这和代码无关，只影响在项目目录里直接运行；打包后的版本不受影响。

**修复**（PowerShell，引号要保留）

```powershell
icacls "E:\projects\github\muse-windows\node_modules\electron\dist" /grant "*S-1-15-2-1:(OI)(CI)(RX)"
```

以后重新 `npm install` 后如果再次出现，对整个 `node_modules` 运行一次：

```powershell
icacls "E:\projects\github\muse-windows\node_modules" /grant "*S-1-15-2-1:(OI)(CI)(RX)" /T /Q
```
